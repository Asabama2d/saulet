# Saulet: результаты технического обзора 24.09.2026

Основа уже полезна для предпроекта: четыре назначения, расчёт состава помещений,
прослеживаемое обоснование площадей, ручные правки, функциональные связи и выгрузки.
Следующий этап — достоверность базы и удобство ведения нескольких вариантов объекта.

## Исправлено в этой доработке

| Проблема | Результат |
|---|---|
| Открытие JSON проверяло только `app`, а localStorage загружался без проверки | Общий валидатор, проверка параметров и ручных связей, импорт без частичной замены состояния |
| JSON терял раскладку, окраску и фильтры потоков | Настройки включены в экспорт и восстановление, старые файлы получают значения по умолчанию |
| Ошибка автосохранения могла остаться незаметной | Уведомление, скачивание исходных повреждённых данных, блокировка их перезаписи до явного возобновления |
| Смена назначения стирала текущую работу сразу | Подтверждение замены и отдельная кнопка сохранения JSON |
| `undergroundFloors` ТРЦ отсутствовали в списке этажей | Общий список уровней для проверок и диаграммы, подписи подземных этажей в выгрузках |
| Повторы кода `A` могли выдать номер `A-1`, уже занятый другим помещением | Нумерация учитывает все исходные коды и уже выданные номера |
| Боковые панели занимали 640 px даже на узком экране | Переключаемые панели, ограниченные по ширине диалоги, свёрнутые слои и легенда |
| Не было тестов и CI | Регрессионные проверки расчётов, графа, файлов, хранилища и экспорта; GitHub Actions |
| README описывал лишь два назначения | Документация приведена в соответствие с кодом |

## Приоритеты следующих этапов

1. **Аудит нормативной базы.** В `norms.json` версия `0.1.0-seed` и дата 27.07.2026,
   а ссылки внутри типов имеют собственные редакции и флаги `verified`.
   Нужны единый реестр редакций, страницы/URL первоисточников, дата и автор сверки,
   история изменения чисел. Флаг сверенной цитаты следует отличать от подтверждения
   действия документа на дату проекта. В этой доработке нормативные числа и статусы
   не пересматривались.
2. **Именованные проекты и варианты.** Сейчас браузер хранит один проект, остальные
   доступны через JSON. Нужны список объектов, дублирование варианта, сравнение состава,
   площадей и отступлений, отмена/повтор изменений. Сервер для локального списка не обязателен.
3. **Показатели по назначению.** Сводка выводит общие «группы/места» для всех объектов.
   Для ТРЦ нужны GLA, торговая площадь и парковка; для ЛПУ — посещения, койки и отделения.
   Коэффициент K и высота этажа у ЛПУ/ТРЦ сейчас берутся из запасных значений движка:
   их стоит сделать явными проектными параметрами с объяснением происхождения.
4. **Точнее работать с повторяемыми помещениями.** Назначение этажа хранится по id
   шаблона помещения. Для размещения разных экземпляров на разных этажах потребуется
   отдельная идентичность физического помещения и миграция проектов.
5. **Связать замечание с действием.** Клик по проверке должен выбирать помещение на
   схеме или строку экспликации; нужны фильтр проблемных позиций и явный статус исправления.
6. **Сценарии браузерных тестов в CI.** Добавить импорт/экспорт через реальные кнопки,
   редактирование помещения и связи, перетаскивание между этажами, проверки узкого экрана.
   Текущие автоматические тесты проверяют функции и хранилище; интерфейс проверен вручную.

Не следует выдавать диаграмму функциональных связей за готовую геометрическую
планировку или полный нормоконтроль. Для этого понадобятся геометрия, эвакуационные
расстояния, проёмы, инсоляция и отдельная проверка применимости норм.
